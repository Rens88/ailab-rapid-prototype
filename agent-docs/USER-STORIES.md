# User Stories

## Overview

This file captures the earliest user stories for the first workshop prototype.

These stories are intentionally scoped for speed. They focus on whether the concept is understandable, believable, and worth pursuing before more engineering effort is invested.

---

# Primary User

The first user is usually a stakeholder, domain expert, customer, or colleague who can judge whether the idea solves a meaningful problem.

The first builder is usually a workshop participant using AI tooling to turn a vague idea into something concrete.

---

# Core User Stories

## Story 1: Understand The Promise

As a first-time visitor,  
I want to understand what the prototype helps me do within the first minute,  
so that I can decide whether it is worth trying.

## Story 2: Start From A Working Example

As a tester,  
I want to begin with example data or a demo scenario,  
so that I can experience the full flow even if I do not bring my own data.

## Story 3: Provide A Small Amount Of Input

As a user,  
I want to enter or select a few realistic inputs,  
so that the prototype feels relevant to my situation without requiring a lot of setup.

## Story 4: Narrow The Scenario

As a user,  
I want to choose the case, record, persona, or situation I care about,  
so that the result is focused instead of generic.

## Story 5: Receive A Concrete Output

As a user,  
I want the prototype to produce a clear recommendation, draft, analysis, or result,  
so that I have something tangible to react to.

## Story 6: Inspect Why The Result Was Produced

As a skeptical user,  
I want to see the evidence, assumptions, or summary behind the output,  
so that I can judge whether the result is trustworthy.

## Story 7: Ask For A Different Emphasis

As a user,  
I want to refine or steer the output without restarting from scratch,  
so that I can explore whether the concept adapts to my intent.

## Story 8: Try A Second Scenario Quickly

As a stakeholder,  
I want to change one or two conditions and see what happens,  
so that I can understand the boundaries of the concept during a live discussion.

## Story 9: Leave Immediate Feedback

As a tester,  
I want to record my reaction while the experience is still fresh,  
so that the builder can use that feedback in the next iteration.

---

# Builder Stories

## Story 10: Finish A Shareable Artifact

As a workshop participant,  
I want a prototype format that I can complete in a short session,  
so that I leave the workshop with something real instead of just notes.

## Story 11: Iterate With AI Quickly

As a workshop participant,  
I want the prototype to be simple enough that an AI coding assistant can revise it quickly,  
so that I can test multiple ideas in a limited amount of time.

## Story 12: Collect Direction For The Next Build

As a workshop participant,  
I want early feedback to reveal what deserves real engineering effort next,  
so that I do not overbuild the wrong thing.

---

# Acceptance Criteria For The First Prototype

- Each core story can be demonstrated in one short session
- The prototype works with mocked or example data
- The user can move from input to output without facilitator intervention
- The output is specific enough to trigger agreement, disagreement, or questions
- The prototype can be shared immediately after the workshop
